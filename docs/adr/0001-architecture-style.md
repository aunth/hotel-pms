# ADR-001. Архітектурний стиль системи

**Статус:** accepted

## Контекст

Система об'єднує F1–F7 для готелю на 50–150 номерів: 30 одночасних користувачів, розгортання в Docker однією командою, розробка і супровід силами одного розробника. Правильність розрахунків і відсутність подвійного бронювання важливіші за швидкість.

## Розглянуті варіанти

2-tier клієнт-сервер, 3-tier з модульним монолітом (N-layer), Hexagonal, мікросервіси, Event-Driven.

## Рішення

Трирівнева клієнт-серверна архітектура. Сервер – модульний моноліт з рівнями Presentation, Application, Domain, Infrastructure і послабленою ізоляцією: Presentation викликає лише Application, Application може звертатися до Domain та Infrastructure, Domain не залежить від інших рівнів. Зовнішні системи підключаються через порти й адаптери.

## Обґрунтування

Один сервер і одна БД дають прості транзакції для броні й рахунку; одна точка входу з перевіркою ролей на сервері; один контейнер для розгортання; модулі тестуються окремо.

## Наслідки

Плюси: просте розгортання, цілісність даних. Мінуси: масштабування переважно вертикальне, межі модулів тримаються на дисципліні. Рішення варто переглянути, якщо система вийде за 300 номерів.
